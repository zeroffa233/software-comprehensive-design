## 1. litemall

- **项目名 + 地址**：litemall（linlinjava/litemall）—— https://github.com/linlinjava/litemall
- **概览**：Spring Boot 后端 + Vue 管理端 + 微信小程序用户端 + MySQL，MIT 许可；含商品、分类、购物车、下单、订单、售后完整链路。
- **可借鉴点**：
  - "后端 / 管理端 / 小程序端 / 公共 db 模块"的分模块工程结构，与我们 DESIGN.md §2 前后端分离 + 双端架构一致，目录划分可直接参照；
  - 购物车与订单模块的表设计（cart 与 order 分离、订单内冗余商品快照字段），支持了 report/06"成交价快照"的决策；
  - 管理端订单列表的筛选（状态 Tab + 关键词）交互，与 report/06 §3.3 订单列表页设计吻合。
- **与本项目差异**：litemall 面向真实电商（微信支付、优惠券、运费、售后退款），业务复杂度远超课程范围；本项目为校园二手，单价低、一单一商品（第一版）、用模拟支付替代微信支付，砍掉优惠券/运费/售后，保留"浏览→购物车→下单→支付→完成"主干。

## 2. newbee-mall

- **项目名 + 地址**：newbee-mall（newbee-ltd/newbee-mall）—— https://github.com/newbee-ltd/newbee-mall
- **概览**：Spring Boot + MyBatis + Thymeleaf 的 Web 商城教学项目，另有 Vue3 前后端分离版；含购物车、订单、分类、搜索、后台管理。
- **可借鉴点**：
  - 订单号生成与"未支付超时取消"的定时任务思路，对应我们 report/06 的"30 分钟未支付自动取消"；
  - 购物车条目的勾选/全选与结算校验的前端交互流，可映射到原型 cart.html 的输入项；
  - 错误码与统一返回结构的组织方式，佐证了我们 design/接口规范总则.md 的 `{code,msg,data}` 方案。
- **与本项目差异**：newbee-mall 是 B2C 新品商城（商家上架、库存充足、面向公众），无用户间买卖关系；本项目 C2C 二手，一个用户既是买家也是卖家，订单需同时服务 buyer_id 与 seller_id 两侧视图（db-购物交易.md 的 orders.seller_id 冗余即为此设计）。

## 3. CampusWall

- **项目名 + 地址**：CampusWall（light-misty/CampusWall）—— https://github.com/light-misty/CampusWall
- **概览**：校园墙综合平台，Spring Boot 3 后端 + 原生微信小程序 + Vue3 Element Plus 管理端，MySQL/Redis/JWT。
- **可借鉴点**：
  - 技术选型与我们几乎一致（SpringBoot + 原生小程序 + Vue3 管理端 + Redis），其小程序端页面结构（信息流/详情/发布）可对照设计我们的商品流页面；
  - 管理端对违规信息的处理流（管理员下架 + 原因），与 report/05 管理员下架违规商品、report/04 封禁用户的审核类操作同构；
  - Redis 缓存热门内容的用法，对应我们 NFR-01"热门商品列表命中 Redis"。
- **与本项目差异**：CampusWall 重社交发布（校园墙、互动、WebSocket 私聊），交易只是其一部分；本项目以交易为核心，第一版明确不做即时聊天（DESIGN.md §1"第一版不做"），互动收敛为订单与可选评价。

## 4. campus_sec_deal

- **项目名 + 地址**：campus_sec_deal（Inetgeek/campus_sec_deal）—— https://github.com/Inetgeek/campus_sec_deal
- **概览**：校园二手交易 SpringBoot 后端 + MySQL 脚本（Apache-2.0），覆盖注册登录、商品发布、下单/支付/取消/完成订单、订单超时取消、商品与订单搜索、钱包充值提现。
- **可借鉴点**：
  - 其订单状态集合与超时取消方案和我们 report/06 状态机高度相似，可对照其实现思路校准 Service 层状态迁移的写法（与 NFR-08"状态机收敛在单一服务类"呼应）；
  - 数据库脚本随仓库提供，表命名与索引可作 db-购物交易.md 的对照样例；
  - 交易私聊、钱包提现等模块被我们主动裁剪，说明中等规模裁剪的可行性边界。
- **与本项目差异**：纯后端无小程序端；含钱包/提现等资金模块（涉及真实资金风险），本项目第一版不涉及任何资金流，仅模拟支付状态变更，安全边界更小。

## 5. Secondhand-goods-on-campus

- **项目名 + 地址**：校园二手交易微信小程序（zhuyuzhu/Secondhand-goods-on-campus）—— https://github.com/zhuyuzhu/Secondhand-goods-on-campus
- **概览**：微信小程序（约 540+ Stars），含商品分类、搜索、购物车、发布、订单、身份验证，另有校园定位与兼职信息等校园特色功能。
- **可借鉴点**：
  - 小程序页面组织（首页分类导航 → 列表 → 详情 → 购物车 Tab）与我们原型的底部导航 + 页面流转一致，原型页面命名（cart/order 等）可参照其 tab 结构；
  - 校园场景的附加功能取舍：校园定位、兼职信息属于"锦上添花"，我们在需求阶段已按 DESIGN.md §1 三级裁剪明确不进第一版，避免范围蔓延；
  - 其 README 自述部分功能较简单——提示我们在原型阶段只保"页面流转与输入项"，不追求美化。
- **与本项目差异**：无独立自建后端（依赖小程序自身体系），鉴权与管理端能力弱；本项目必须有 RBAC + 管理端 + 操作日志（课程硬性要求），因此其鉴权部分不可借鉴，仅取页面交互。

## 6. 小结

| 项目 | 主要借鉴维度 | 明确不借鉴的部分 |
|---|---|---|
| litemall | 工程分模块结构、订单快照设计 | 优惠券/运费/真实支付/售后 |
| newbee-mall | 订单超时取消、购物车交互 | B2C 商家模型 |
| CampusWall | 技术栈验证、管理端审核流 | 社交/即时聊天/校园墙 |
| campus_sec_deal | 订单状态机实现思路 | 钱包提现等资金模块 |
| Secondhand-goods-on-campus | 小程序页面流转 | 弱鉴权（不满足 RBAC 要求） |

> 共同结论：五个项目均验证了"浏览→购物车→下单→（模拟）支付→订单状态流转"是二手/商城类系统的稳定主干，本组 report/06 的范围裁剪合理；真实支付、即时聊天、资金模块是课程范围内的普遍裁剪项。
